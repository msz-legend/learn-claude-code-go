## 課題

セッションは毎回ゼロから始まり、同じプロジェクト事実を何度も発見する。すべてをプロンプトに入れるのは問題の場所を移すだけだ。

## 仕組み

1. 要求前にストアを全部渡さず、関連する項目を選ぶ。
2. 終わったやり取りから耐久性のある事実を少数抽出する。
3. 重複を統合し、上限を設けてストアを使いやすく保つ。

## コードマップ

| File | Role |
|---|---|
| `s09_memory/main.go` | 本章の入口。この仕組みを1つのループに接続する。 |
| `internal/harness/memory.go` | 全章で共有する実装。 |
| `.memory/` | 本章が書き出す状態。 |

## 実行

```bash
go run ./s09_memory
```

初回実行前に .env.example を .env にコピーし、いずれかのプロバイダーを設定してください。認証情報がなくても --help は動きます。

## 試してみる

- ビルドコマンドを覚えさせ、再起動後に recall する。
- 似た項目を追加し、consolidate_memory を実行する。
