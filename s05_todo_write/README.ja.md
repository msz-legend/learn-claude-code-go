> 計画をハーネスに置けば、いつでも再表示できる。

---

## 課題

長い作業は漂流する。モデルは計画を忘れ、同じ仕事を繰り返し、工程を黙って落とす。プロンプトだけの計画は次の要約で消える。

## 仕組み

1. pending、in_progress、completed の状態を持つ順序付きリストを保存する。
2. 進行中は最大1件に限り、次の行動を曖昧にしない。
3. ツールのラウンド数を数え、計画が古くなったら再注入する。

## コードマップ

| ファイル | 役割 |
|---|---|
| `s05_todo_write/main.go` | 本章の入口。この仕組みを1つのループに接続する。 |
| `internal/harness/todo.go`, `internal/harness/hooks.go` | 全章で共有する実装。 |

## 実行

```bash
go run ./s05_todo_write
```

初回実行前に .env.example を .env にコピーし、いずれかのプロバイダーを設定してください。認証情報がなくても --help は動きます。

## 試してみる

- 3ステップの作業を頼み、各ステップ後に /todo を見る。
- 数ラウンド更新せずに、リマインダーが出ることを確認する。
